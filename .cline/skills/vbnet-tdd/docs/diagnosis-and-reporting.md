# 失敗の切り分けと完了報告

## 失敗の切り分け

テストが失敗したら、次の順で原因を分ける。

1. **コンパイル**: Imports、参照、型、アクセス修飾子、Option設定
2. **テスト検出**: 属性、Public、アダプター、Target Framework、出力DLL
3. **実行環境**: 作業ディレクトリ、環境変数、ファイル、DB、権限、Platform
4. **テストコード**: Arrange、入力、期待値、モックやスタブ
5. **本実装**: 契約、状態変化、例外、境界条件

最初の失敗とスタックトレースを確認する。複数の失敗を推測でまとめて直さず、最小の再現から1件ずつ扱う。

コンパイルエラー、テスト未検出、依存関係のエラーは、TDDのRedとは数えない。テスト環境を直してから、改めてRedを確認する。

## 完了条件

次を満たすまで完了と報告しない。

- 要件に対応するテストがある
- 期待した理由でRedになったことを確認している
- 最小実装でGreenになっている
- Refactor後も対象テストが通っている
- 関連テストと、可能なら全テストが通っている
- ビルドが通っている
- 実行したコマンドやTest Explorerの操作を再現できる
- 未実行テストと理由を説明できる

## 完了報告のテンプレート

```text
対象:
- ソリューション:
- プロジェクト:
- Target Framework:
- Configuration / Platform:
- テストフレームワーク / アダプター:

TDD:
- Red:
- Green:
- Refactor:

検証:
- 実行したコマンド:
- 対象テスト:
- 関連テスト:
- 全テスト:
- ビルド:

変更:
- ファイル:
- コミット:

未解決:
- なし、または内容と理由
```

テストを実行できなかった場合は、成功したように報告しない。未実行の理由、代わりに確認したこと、残っているリスクを明記する。
